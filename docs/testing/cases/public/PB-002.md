# Post footer hidden when display footer is disabled

## Scenario

PublishPress Future (free) is active. Display settings have the post footer **disabled**. A **published** post has an enabled future action scheduled **7 calendar days ahead at 12:00** (site timezone), action **Change status to Draft**. The action queue is **not** run—the post stays published for front-end checks.

## Steps

1. As an administrator, open **Future Actions → Display** (`wp-admin/admin.php?page=publishpress-future&tab=display`).
2. Disable **Show in Post Footer?** (`expired-display-footer` = Disabled).
3. Optionally set **Footer Contents** (`expired-footer-contents`) to a distinctive string (e.g. containing `ACTIONFULL`) to prove it would be obvious if it appeared; save changes.
4. Use the fixture post: status **Published**, future action **enabled**, date **7 days from today**, time **12:00**, action **Change status to Draft**. Do not run the queue.
5. Log out (or use a private/incognito window).
6. View the fixture post on the front end.
7. Inspect the post content area and typical footer/hook output locations for PublishPress Future footer markup or the configured footer text.

## Expected result

- The front end does **not** display the configured **Footer Contents** (no action-date footer block from PublishPress Future for this post).
- Normal post content still renders; absence of the footer is the pass condition.

## Edge cases

- A `[futureaction]` shortcode in post content is independent of footer settings—this case assumes post body does not rely on the shortcode unless you intentionally add one (then expect shortcode output but still no footer block).
- Caching/CDN may serve stale HTML; bypass or purge cache if a previous run had footer enabled.
