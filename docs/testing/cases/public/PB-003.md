# futureaction shortcode shows action date on the front end

## Scenario

PublishPress Future (free) is active. **Show in Post Footer?** is **disabled** so the action date is not duplicated in the post footer. A **published** post’s body contains **only** the shortcode `[futureaction]` (tag `futureaction`; do not use the deprecated `postexpirator` alias). The post has an enabled future action scheduled **7 calendar days ahead at 12:00**, action **Change status to Draft**. The queue is **not** run.

## Steps

1. As an administrator, open Display settings (`wp-admin/admin.php?page=publishpress-future&tab=display`).
2. Disable **Show in Post Footer?** (`expired-display-footer`).
3. Set **Date Format** (`expired-default-date-format`) and **Time Format** (`expired-default-time-format`) to known values if you need deterministic assertions (defaults are acceptable if documented in the test run).
4. Ensure **Shortcode Wrapper** does not hide output unexpectedly (e.g. **— None —** is fine).
5. Create or edit the fixture post: set post content to exactly `[futureaction]` and publish.
6. Configure the future action: **enabled**, **7 days ahead**, **12:00**, **Change status to Draft**.
7. Log out and view the post on the front end.

## Expected result

- The front end shows the scheduled action date/time rendered by the `[futureaction]` shortcode (default `type` is full date+time per Display settings help).
- No PublishPress Future footer block appears (footer display is off).
- The visible shortcode output corresponds to the fixture’s scheduled action (seven days ahead at 12:00), not an empty or placeholder string.

## Edge cases

- Shortcode attributes `type`, `dateformat`, and `timeformat` override defaults—this case uses bare `[futureaction]` only.
- If the post has no enabled future action, shortcode output may be empty; the fixture must have an active scheduled action.
- Theme content filters may wrap shortcode output; assert on the substituted date/time, not wrapper markup.
