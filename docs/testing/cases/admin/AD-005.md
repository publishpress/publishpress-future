# Taxonomy for post default action persists

## Scenario

The administrator selects **Tags** for the **post** taxonomy control when configuring a taxonomy-related default action; the selection persists after save and reload.

## Steps

1. Sign in as an administrator.
2. Open `wp-admin/admin.php?page=publishpress-future&tab=defaults`.
3. For **post**, if **Taxonomy** (`expirationdate_taxonomy-post`) is not visible, set **Default Action** (`expirationdate_expiretype-post`) to **Add extra tags** (or another taxonomy-related action that reveals **Taxonomy**).
4. Set **Taxonomy** for **post** to **Tags** (`post_tag`).
5. Click **Save changes**.
6. Reload the page.

## Expected result

1. After reload, **Taxonomy** for **post** still shows **Tags** selected.
2. If step 3 changed **Default Action**, that action remains selected so **Taxonomy** stays applicable.

## Edge cases

- If no taxonomy-related **Default Action** exists for **post**, document as blocked and skip taxonomy assertion.
