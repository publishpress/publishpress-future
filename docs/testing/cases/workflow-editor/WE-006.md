# Move workflow to trash from the sidebar

## Scenario

An administrator trashes a published workflow with **Move to trash** in the sidebar summary and accepts the confirmation. The editor closes and the workflow leaves the Published list.

## Steps

1. Sign in as an administrator.
2. Precondition: a published workflow titled `Draft flow QA updated` exists.
3. Open `wp-admin/admin.php?page=future_workflow_editor&workflow={id}`.
4. Open the sidebar summary (settings sidebar) if it is not visible.
5. Confirm **Move to trash** is in the sidebar summary and not in the header.
6. Click **Move to trash**.
7. Accept the confirm dialog with text **Are you sure you want to delete this workflow?**.
8. Open `wp-admin/edit.php?post_type=ppfuture_workflow` and select the **Published** view.
9. Select the **Trash** view.

## Expected result

1. After accepting, the browser leaves the editor URL.
2. The **Published** list does not contain `Draft flow QA updated`.
3. The **Trash** view contains `Draft flow QA updated`.

## Edge cases

- Dismissing the confirm dialog keeps the editor open and the workflow Published.
- The header has no **Move to trash** control.
