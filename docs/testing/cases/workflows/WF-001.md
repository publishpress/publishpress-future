# Action Workflows admin access and editor entry

## Scenario

PublishPress Future (free) with Action Workflows is available. Verify that an administrator can reach the workflow list and editor, and that a subscriber cannot access the workflows admin menu.

## Steps

1. Log in as a user with the **Administrator** role.
2. In wp-admin, open **Action Workflows** (post type `ppfuture_workflow`), URL `wp-admin/edit.php?post_type=ppfuture_workflow`.
3. Confirm the list screen heading reads **Action Workflows**.
4. Click **Add New** (or equivalent control that creates a workflow), which targets `post-new.php?post_type=ppfuture_workflow`.
5. After any redirect, confirm the browser URL contains `page=future_workflow_editor`.
6. Confirm the workflow editor screen is shown (page heading or document title **Action Workflow Editor**).
7. Log out. Log in as a user with only the **Subscriber** role.
8. Scan the wp-admin menu for **Action Workflows** and attempt direct navigation to `wp-admin/edit.php?post_type=ppfuture_workflow` if the menu item is absent.

## Expected result

- **Administrator:** The Action Workflows list loads with heading **Action Workflows**. **Add New** leads to the workflow editor; URL includes `page=future_workflow_editor`; editor title/heading is **Action Workflow Editor**.
- **Subscriber:** **Action Workflows** does not appear in the admin menu. Direct access to the list URL is denied or blocked per WordPress capabilities (no workflow management UI).

## Edge cases

- Custom admin menu plugins may reorder items; locate **Action Workflows** by label, not only position.
- Editor may open in a SPA shell; URL and document title are the primary signals if heading markup differs slightly.
- Multisite: run on a site where the plugin is network- or site-active per your test environment matrix.
