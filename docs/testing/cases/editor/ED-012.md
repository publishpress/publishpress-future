# Corrupted meta loads with checkbox unchecked

## Scenario

The test harness seeds post meta for the future action on a post so that meta **exists** but is **not** a valid action payload (corrupted action data). Opening the post in the block editor must not fatal or blank the screen; **Enable Future Action** appears **unchecked**.

## Steps

1. Log in to **wp-admin** as a user who can edit posts.
2. Ensure **Posts** is active on **Future Actions → Post Types** (`wp-admin/admin.php?page=publishpress-future&tab=defaults`).
3. Using the test harness, create or select a post and seed **corrupted future-action post meta** (invalid payload; exact meta key is defined by the harness/plugin under test).
4. Open **Posts → All Posts** and click **Edit** on that post to load the **block editor**.
5. Observe the editor canvas and sidebar load completely (wait for editor ready state).
6. Open the **Future Actions** panel in the document sidebar.
7. Assert **Enable Future Action** is **unchecked**.
8. Assert there is no blank white editor, no PHP fatal error page, and no blocking error modal from the plugin.

## Expected result

- Block editor loads successfully despite corrupted stored action data.
- **Enable Future Action** is unchecked (plugin treats invalid stored data as no enabled action).
- No PHP fatal and no blank editor screen.

## Edge cases

- Corrupted meta must be seeded by the harness; manual UI steps cannot produce invalid payloads reliably.
- Saving the post after load without enabling should not reintroduce fatal errors; optional smoke save is harness-specific.
