# Manual enable persists with Stick and date

## Scenario

**Automatically create actions** is off for posts. A new post starts with **Enable Future Action** unchecked. The author enables the action, chooses **Stick**, sets a future date and time, saves, and reloads; all values persist.

## Steps

1. Log in to **wp-admin** as a user who can edit posts.
2. Open **Future** at `wp-admin/admin.php?page=publishpress-future&tab=defaults` (Future Actions, Post Types tab).
3. Ensure **Posts** has **Activate the PublishPress Future actions for this post type** checked; save if needed.
4. On the same screen, find **Automatically create actions** (input name `expirationdate_autoenable-post`) and **uncheck** it for posts if checked.
5. Click **Save changes**.
6. Open **Posts → Add New**.
7. In the **Future Actions** panel, assert **Enable Future Action** is **unchecked**.
8. Check **Enable Future Action**.
9. In the **Action** control (or equivalent action dropdown), select **Stick**.
10. Set the expiration **date** to a date at least 7 days in the future (e.g. the 15th of next month).
11. Set the expiration **time** to **09:00**.
12. Note the chosen date and time for later assertions.
13. Click **Save draft** (or **Publish**).
14. Reload the post edit screen (full browser refresh or re-open **Posts → Edit** for this post).
15. In **Future Actions**, assert **Enable Future Action** is **checked**.
16. Assert the **Action** field shows **Stick**.
17. Assert the date and time fields match the values set in steps 10–11.

## Expected result

- Before first save on a new post: **Enable Future Action** is unchecked when auto-create is off.
- After save and reload: checkbox remains checked; action remains **Stick**; date and time match what was saved.

## Edge cases

- Time zone: assert stored/displayed time matches site timezone setting (09:00 as entered in the UI).
- If the date picker only exposes a date, assert the time control separately where the plugin renders it.
