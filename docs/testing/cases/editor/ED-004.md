# Auto-create default checked; uncheck persists

## Scenario

**Automatically create actions** is on for posts. A new post opens with **Enable Future Action** checked by default. The author unchecks it, saves, and reloads; it stays unchecked.

## Steps

1. Log in to **wp-admin** as a user who can edit posts.
2. Open **Future** at `wp-admin/admin.php?page=publishpress-future&tab=defaults` (Future Actions, Post Types tab).
3. Ensure **Posts** has **Activate the PublishPress Future actions for this post type** checked.
4. Check **Automatically create actions** (input name `expirationdate_autoenable-post`) for posts.
5. Click **Save changes**.
6. Open **Posts → Add New**.
7. In the **Future Actions** panel, assert **Enable Future Action** is **checked**.
8. Uncheck **Enable Future Action**.
9. Click **Save draft**.
10. Reload the post edit screen.
11. In **Future Actions**, assert **Enable Future Action** is **unchecked**.

## Expected result

- On a brand-new post with auto-create on: **Enable Future Action** starts checked.
- After unchecking, saving, and reloading: checkbox remains unchecked.

## Edge cases

- Auto-create may pre-create empty action metadata; unchecking should still persist without requiring action/date fields to be filled.
