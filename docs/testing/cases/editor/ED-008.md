# Quick Edit sets action visible on full edit

## Scenario

From **Posts** list, Quick Edit a published post that has no future action. Enable the action, set **Stick** and a future date, update. Opening the full block (or classic) edit screen shows the same checkbox, action, and date.

## Steps

1. Log in to **wp-admin** as a user who can edit posts.
2. Ensure **Posts** is active on **Future Actions → Post Types** (`wp-admin/admin.php?page=publishpress-future&tab=defaults`).
3. Create and **Publish** a post with **no** future action (or use a harness fixture post ID known to have no action).
4. Open **Posts → All Posts**.
5. Hover the target post row and click **Quick Edit**.
6. In the inline Quick Edit form, locate the section titled **Future Actions** (same default panel title as the editor).
7. Check **Enable Future Action**.
8. In the **Action** field, select **Stick**. If the field is empty, leaving it empty and submitting should surface validation **Select an action**; then select **Stick**.
9. Set the **date** to a date at least 7 days in the future (e.g. the 15th of next month). If date is missing, validation **Select a date** may appear; then set the date.
10. Set **time** to **09:00** if Quick Edit exposes a time control.
11. Click **Update** in the Quick Edit row.
12. Wait for the list to refresh without error.
13. Click the post title (or **Edit**) to open the full post edit screen.
14. In **Future Actions**, assert **Enable Future Action** is **checked**.
15. Assert **Action** is **Stick**.
16. Assert the **date** (and **time** if shown) match Quick Edit values.

## Expected result

- Quick Edit uses panel title **Future Actions**, checkbox **Enable Future Action**, and an **Action** field consistent with the main editor.
- Full edit screen reflects Quick Edit choices after **Update**.

## Edge cases

- Validation messages **Select an action** and **Select a date** appear when required fields are missing; automation should only assert them when intentionally triggering validation.
- Block vs classic full editor: assert on whichever editor the site uses; fields must match regardless.
